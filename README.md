# 방해를 0까지 내려 보기 — 「두근두근 물리」 1편 관성 실습

영상 「움직이는 물체는 왜 멈출까?」를 본 뒤, VPyLab에서 코드를 읽고 숫자를 직접 바꿔 보는 실습이에요. 원반과 출발 빠르기(4 m/s), 바닥을 나타내는 숫자(4 · 2 · 1 · 0.5)는 영상과 같아요. 숫자는 모두 설명용이에요.

- 파일: `main.py` 하나(VPyLab 샌드박스에 그대로 붙여 넣거나 주소로 여세요)
- 시간: 기본 15~20분, 심화는 한 차시 더
- 순서: ① 원리 이해하기(코드 읽기) → ② 직접 바꿔 보기(숫자 고치고 실행) → ③ 심화: 직접 개선해 보기(선생님과 함께 / 혼자 해 보기)

## ① 원리 이해하기 — 코드 읽기
`main.py` 맨 위의 '2. 법칙' 부분에 영상 내용이 모두 담겨 있어요.

```python
빠르기 = 빠르기 - 줄어드는_빠르기 * 시간간격   # 방해가 있는 만큼만 빠르기가 줄어든다
if 빠르기 < 0:
    빠르기 = 0                                 # 방해는 멈추게 할 뿐, 뒤로 밀지는 않는다
위치 = 위치 + 빠르기 * 시간간격                # 지금 빠르기로 한 걸음만큼 간다
```

컴퓨터는 1초를 600걸음으로 잘게 나누어 걸음마다 이 네 줄을 되풀이해요. 읽으면서 생각해 보세요.
1. 빠르기를 바꾸는 줄은 어느 줄인가요? 그 줄에서 빠르기를 바꾸는 것은 무엇인가요?
2. `줄어드는_빠르기`가 0이면 첫 줄은 무엇을 하나요? → 영상의 결론 "빠르기를 바꾸는 것이 없으면 빠르기는 그대로"가 바로 이 경우예요.
3. '앞으로 미는 힘'은 코드 어디에 있나요? (없어요. 이미 원반에서 손을 뗐으니까요.) 그런데도 원반은 왜 앞으로 가나요?

# 교사용 안내

## 실습의 뜻
- 영상의 원리인 "빠르기를 바꾸는 것이 없으면 빠르기는 그대로"는 코드의 `빠르기 = 빠르기 - 줄어드는_빠르기 * 시간간격`에서 `줄어드는_빠르기`가 0인 경우에 해당합니다. 학생이 '미는 힘'을 코드에서 찾다가 없다는 것을 알아차리는 순간이 이 실습의 핵심입니다.
- 이 모형은 영상과 같이 '빠르기가 고르게 줄어드는' 설명용 모형입니다. 질량과 F = ma는 2편에서 다루므로 이 실습에서는 '힘' 대신 '1초 동안 줄어드는 빠르기'로만 말합니다.
- 계산 순서는 시리즈 공통 규칙대로 **빠르기 먼저 → 위치**입니다.

## 숫자 확인(검산)
- 멈춘 거리의 참값은 출발 빠르기² ÷ (2 × 줄어드는 빠르기)로 4 → 2 m, 2 → 4 m, 1 → 8 m, 0.5 → 16 m(0.25 → 32 m)입니다.
- 코드는 한 걸음씩 빠르기와 위치를 계산하므로 원반은 언제나 참값보다 **출발 빠르기 × 시간간격 ÷ 2 = 4 × (1/600) ÷ 2 ≈ 0.0033 m(약 3 mm)** 짧게 멈춥니다. 실제 값은 1.9967 · 3.9967 · 7.9967 · 15.9967 m이고, 화면에는 소수 첫째 자리까지 2.0 · 4.0 · 8.0 · 16.0 m로 보입니다. 점 개수 1 · 2 · 4 · 8개도 영상과 같습니다.
- 방해가 0이면 점이 4 m 간격으로 찍힙니다. 원반이 62 m를 지나면 '아직 멈추지 않았어요'라는 알림이 뜨고 원반이 더 가지 않습니다(그동안 화면은 원반을 따라갑니다).
- '혼자 해 보기'의 마지막 과제는 멈춘 거리와 참값의 차이가 시간간격에 비례한다는 것을 확인하는 것입니다. 시간간격이 1이면 카펫에서 멈춘 거리가 0 m로 나옵니다(첫 걸음에 빠르기가 바로 0이 되기 때문입니다).

## 선생님과 함께 — 단계별 심화
각 단계는 '물음 → 고칠 부분 → 확인'의 순서로 진행합니다. 고친 코드 예시는 `solutions/README.md`에 있습니다(학생에게는 나중에 보여 줍니다).

### 1단계: 두 힘이 서로 지워질 때 (영상 장면 9)
- 물음: "방해가 0인 판 위에서 앞으로 미는 힘과 뒤로 당기는 힘을 똑같이 주면 빠르기는 어떻게 될까?"
- 고칠 부분: '1. 바꿔 볼 숫자'에 `미는_빠르기`, `당기는_빠르기`(1초 동안 빠르기를 바꾸는 양)를 추가하고, '2. 법칙'의 첫 줄에서 이 둘을 더하고 뺍니다.
- 확인: 둘 다 1이면 점 간격이 4 m로 유지됩니다. 미는 쪽만 1이면 간격이 늘어나고, 당기는 쪽만 1이면 줄어듭니다.
- 예상되는 어려움: 당기는 힘만 주었더니 원반이 8 m에서 멈춰 버립니다. → 도움말: "`if 빠르기 < 0`은 마찰을 위한 줄이에요. 당기는 힘은 원반을 뒤로 보낼 수 있을까요?" (마찰과 당기는 힘의 차이를 이야기할 기회입니다.)

### 2단계: 빠를수록 방해가 커지는 바닥
- 물음: "물속이나 공기처럼 빠를수록 방해가 커지면 점 간격은 어떻게 줄어들까?"
- 고칠 부분: `줄어드는_빠르기 * 시간간격`을 `비율 * 빠르기 * 시간간격`으로 바꿉니다.
- 확인: 비율이 0.5이면 점 간격이 매번 같은 비율로 줄어듭니다. 원반의 위치는 약 8 m에 가까워지지만 아주 오래 걸립니다.
- 예상되는 어려움: 원반이 영영 멈추지 않습니다(빠르기가 0에 가까워질 뿐 0이 되지 않습니다). → 도움말: "아주 느리면 멈춘 것으로 치는 줄을 하나 넣어 볼까요?" (`if 빠르기 < 0.01: 빠르기 = 0`)

### 3단계: 두 원반을 나란히 내보내기
- 물음: "카펫과 얼음을 한 화면에서 동시에 비교하려면 무엇이 두 개씩 있어야 할까?"
- 고칠 부분: 원반 · 빠르기 · 위치 · 줄어드는 빠르기를 두 벌로 만들고, 두 원반의 z 위치를 다르게 설정합니다. 루프에서는 각 원반에 대해 `한_걸음`을 호출합니다. `한_걸음`이 `줄어드는_빠르기`를 매개변수로 받도록 바꿔야 합니다.
- 예상되는 어려움: 두 번째 원반도 첫 번째와 똑같이 움직입니다. → 도움말: "`한_걸음` 안의 `줄어드는_빠르기`는 어느 원반의 값을 쓰고 있나요?"

## 수업 운영 메모
- 슬라이더는 보조 도구입니다. 기본은 코드의 숫자를 고쳐 [실행]하는 것이고, 휴대폰처럼 코드 고치기가 어려울 때만 슬라이더를 씁니다.

- '관성 때문에'라는 말로 설명을 끝내지 않게 합니다. 영상에서와 마찬가지로 관성을 힘처럼 표현하지 않도록 지도합니다.
